# 사용 및 운영 흐름

## LLM Wiki 동작 구조

```text
사용자와 LLM의 대화
        |
        v
     cs-wiki ------ 작성, 갱신, 점검 ------> knowledge/
                                                |
                                                | 읽기 전용 정답 기준
                                                v
사용자 <------ 질문, 꼬리 질문, 평가 ------ cs-interviewer
                                                |
                                                v
                                      records/ 개인 기록
```

`cs-wiki`와 `cs-interviewer`는 같은 지식 번들을 사용하지만 쓰기 권한은 분리한다. `cs-wiki`만
`knowledge/`를 변경하며, `cs-interviewer`는 위키를 읽기만 하고 개인 결과는 `records/`에 저장한다.

## 지식 축적

### 개념을 바로 정리하기

```text
"데이터베이스의 MVCC를 위키에 정리해줘"
```

LLM은 루트 인덱스와 분야별 인덱스를 읽고 `분야 > 큰 토픽`을 결정한다. 기존 페이지가 없으면 새로
작성하고, 있으면 내용을 보존하면서 새 지식을 병합한다. 개념 페이지, 인덱스, 교차링크, 변경 로그를
함께 갱신한 뒤 구조를 점검한다.

### 대화하며 정리하기

```text
"트랜잭션 격리 수준을 이야기하면서 정리하자"
```

LLM은 한 번에 한 질문으로 개념을 탐색한다. 대화가 한 매듭 지어지면 나온 내용을 신규, 갱신,
변경 없음으로 분류하고 저장할 변경을 제안한다. 사용자가 승인한 내용만 위키에 반영한다.

### 다음 학습 주제 추천받기

```text
"운영체제에서 다음에 공부할 것을 추천해줘"
```

LLM은 [학습 로드맵](./ROADMAP.md)과 실제 개념 링크를 비교한다. 비어 있거나 작성량이 적은 큰 토픽,
기존 개념의 선수 지식과 면접 빈출도를 바탕으로 아직 작성되지 않은 개념을 추천한다.

### 위키에서 질의하기

```text
"지금 위키에 정리된 TCP 연결 수립 과정을 설명해줘"
```

답변은 실제 개념 페이지를 근거로 만든다. 큰 토픽 제목만 있고 개념 페이지가 없으면 작성된 지식이
없다고 밝힌다. 위키 밖의 일반 지식을 보충하면 위키 근거가 아니라는 점을 구분한다.

### 위키 점검하기

```text
"위키 전체를 점검해줘"
```

로드맵 구조, 중복 등록, 끊긴 링크, 고아 페이지, 모순, 낡은 서술을 보고한다. 점검 단계에서는
자동으로 고치지 않으며 사용자 승인을 받은 항목만 수정한다.

## 모의 면접

```text
"CS 전체에서 모의 면접 보자"
"네트워크의 전송 계층만 연습하자"
"프로세스와 스레드 개념으로 꼬리 질문을 해줘"
```

출제 범위는 전체, 분야, 큰 토픽, 개별 개념으로 지정할 수 있다. 인덱스의 큰 토픽 아래 링크되어 있고
실제로 존재하는 `type: CS Concept` 페이지만 후보가 된다. 약점 기록이 있으면 약 60%를 약점 개념에
배정하고 나머지는 범위 안에서 섞는다.

면접관은 한 번에 한 질문만 하고 실제 사용자 답변을 기다린다. 세션이 끝나면 질문과 답변 원문,
첨삭, 점수, 약점을 `records/`에 저장해 다음 출제 계획에 사용한다.

## 데이터 경계

| 경로 | 내용 | Git 공개 |
|---|---|---|
| `knowledge/` | 검토된 CS 지식과 로드맵 | 예 |
| `skills/` | LLM의 작성 및 면접 워크플로우 | 예 |
| `benchmarks/` | 스킬 회귀 검사와 건강도 측정 | 예 |
| `records/` | 답변 원문, 점수, 약점, 숙련도 | 아니요 |

개인 기록을 지식 페이지에 복사하지 않는다. 면접관도 지식 번들을 수정하지 않는다.

## 설치와 경로 설정

사용자 스킬 홈에 두 스킬을 연결하거나 복사한다.

```bash
ln -s "$(pwd)/skills/cs-wiki" ~/.agents/skills/cs-wiki
ln -s "$(pwd)/skills/cs-interviewer" ~/.agents/skills/cs-interviewer
```

`skills/cs-wiki/workflow.md`의 `wiki_root`와 `skills/cs-interviewer/workflow.md`의 `wiki_root`가
같은 `knowledge/`를 가리켜야 한다. 면접 기록의 `records_root`는 공개 저장소 밖이나 Git에서 제외한
`records/`로 둔다.

## 품질 확인

결정론적 grader와 측정 기준은 [`benchmarks/`](../benchmarks/README.md)에 있다.

```bash
node --test benchmarks/grader.test.mjs
node benchmarks/grader.mjs health knowledge
```

첫 명령은 인덱스의 큰 토픽 배치 규칙을 회귀 검사한다. 두 번째 명령은 교차링크 밀도, 역링크 완전성,
고아 페이지 비율을 계산한다.
