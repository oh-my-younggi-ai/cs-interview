# Step 2: 면접 진행 - 핵심 용어 정의 → 답변 → 키워드 → 꼬리 질문

면접의 핵심 루프. 한 개념씩, 핵심 용어 정의 질문 → 세부 메인 질문 → 답변 기반 꼬리 질문으로 깊이 파고든다.

## RULES

- **한 번에 한 질문, 질문 직후 턴 종료.** 짧은 응답 신호와 질문 표지는 질문의 맥락을 밝히기 위한 것이며, 질문은 항상 한 개만 출력한다. 질문을 출력하면 그 응답을 거기서 끝내고
  사용자의 실제 답변을 기다린다. **HALT는 "응답을 멈추고 사용자 입력을 받는다"는 뜻이다.**
- **사용자 답변을 절대 대필/추측하지 않는다.** 한 응답 안에 사용자의 답변을 지어내 채우거나,
  답변이 온 것처럼 가정하고 평가, 다음 질문으로 넘어가서는 안 된다. 사용자 입력 메시지가
  실제로 도착했을 때만 다음 단계를 진행한다. (이걸 어기면 면접이 가짜가 된다.)
- 정답을 미리 다 알려주지 않는다. 면접관처럼 답변을 끌어내고 파고든다.
  (상세 평가, 모범답안은 세션 끝 step-03에서 정리한다.)
- 평가 기준은 해당 위키 개념 페이지다. 페이지의 `# 핵심 개념`, `# 헷갈리는 점`을 정답, 함정 기준으로 쓴다.
- `{wiki_root}`는 읽기만 한다. 면접 중 어떤 위키 파일도 수정하지 않는다.
- **EARLY EXIT** = 이 step을 즉시 중단하고 지정된 파일로 이동한다.

## INSTRUCTIONS - 현재 개념 1개 처리

### 1. 개념 페이지 로드 (읽기 전용)

`{concept}` = `{plan}[{current_index}]`. 위키에서 해당 개념 페이지를 읽어
`# 한 줄 정의`, `# 핵심 개념`, `# 면접 단골 질문`, `# 헷갈리는 점`을 파악한다. 주제명과 세부
질문을 이해하기 전에 정의가 필요한 최소 용어를 `{core_terms}`로 정한다. 페이지 제목의 중심 개념을
우선하고, 비교 페이지라면 비교 대상 중 아직 이번 세션에서 정의를 확인하지 않은 용어를 포함한다.
구현 세부사항이나 함정에만 등장하는 단어는 핵심 용어로 확장하지 않는다.

현재 개념을 처음 시작할 때 `{question_phase}=definition`으로 설정한다. 이번 세션에서 앞서 정확한
정의를 확인한 용어는 `{defined_core_terms}`에 유지하고 다시 묻지 않는다.

### 2. 메인 질문

`{core_terms}` 중 첫 용어를 `{current_core_term}`으로 정하고, 그 용어가 무엇인지 정의하게 하는
질문을 만든다. 정의 질문에는 동작 원리, 장단점, 비교, 사례를 함께 묻지 않는다. 핵심 용어가 여러
개라면 한 번에 하나만 묻고, 현재 용어의 정의가 확인된 뒤 다음 용어를 묻는다. 이번 세션의 앞선
개념에서 이미 정확한 정의를 확인한 용어는 다시 묻지 않는다.

모든 핵심 용어의 정의가 확인되면 `{question_phase}=detail`로 바꾼다. 이때에만 `# 면접 단골 질문`에서
세부 질문을 고르거나, 없으면 `# 핵심 개념`에서 동작 원리, 비교, 예외, 적용을 묻는 질문을 만든다.
질문만 제시한다 (몇 번째/총 몇 개인지 한 줄로 같이).

> **[{current_index+1}/{총 개수}] {주제}**
> {메인 질문}

**여기서 응답을 끝낸다(턴 종료).** 사용자의 실제 답변이 도착할 때까지 아무것도 더 출력하지 않는다.
답변이 오기 전에는 step 3 이후로 진행하지 않는다.

### 3. 답변 분석 - 키워드 추출

사용자 답변에서:
- **언급한 키워드/주장**을 뽑고, 각각을 `정확`, `모호`, `오해`, `누락`으로 분류한다.
- 위키 `# 핵심 개념` 대비 **빠뜨린 핵심**, `# 헷갈리는 점` 대비 **건드린 함정/오해**를 파악한다.
- 꼬리질문의 출발점으로 삼을 **답변 근거**를 하나 고른다. 답변 근거는 사용자가 실제로 말한
  주장이나 표현이며, 원문 인용 또는 뜻을 보존한 짧은 요약으로 기록한다.
- **사용자 답변 원문**과 직전 질문 원문을 `{transcript}`의 현재 개념 항목에 그대로 보존하고,
  분석 메모(강점/놓친 점/첨삭거리/꼬리거리/답변 근거)를 함께 누적한다. 원문은 요약하지 않는다.
  step-03 보고서가 대화를 원문 그대로 옮기고 틀린 답변 아래 첨삭을 단다.

현재 질문이 핵심 용어 정의 질문이면 그 용어의 본질과 경계를 설명했는지 먼저 판단한다. 정확한
정의가 확인되지 않았다면 세부 질문으로 넘어가지 않고 같은 용어를 더 좁혀 한 번 묻는다. 정의가
확인되면 `{current_core_term}`을 `{defined_core_terms}`에 추가한다. 남은 `{core_terms}`가 있으면
다음 용어의 정의 질문 하나를 출력하고 턴을 끝낸다. 모두 확인되면 `{question_phase}=detail`로 바꾸고
세부 메인 질문 하나를 출력한 뒤 턴을 끝낸다. 정의 질문과 그 확인 질문은
`{max_followups_per_concept}`에 포함하지 않는다.

힌트 뒤에도 핵심 용어를 정의하지 못하면 정의 부족을 약점으로 기록한다. 정답을 공개하지 않은 채
현재 개념을 마치고 다음 개념으로 이동한다. 정의를 확인하지 못한 상태에서 세부 질문을 출제하지 않는다.

사용자가 "모르겠어요/패스"라고 하거나 핵심 표현이 모호하면: 정답을 말하지 않는 한 문장짜리
힌트를 준 뒤, 같은 쟁점을 더 좁혀 다시 답하게 한다. 힌트는 사고의 축만 제공한다. 예를 들어
소유권이 쟁점이면 "획득한 주체와 해제하는 주체의 관계를 먼저 생각해보세요"라고 말한다.
힌트 후에도 답하지 못하면 약점으로 기록하고 다음 질문 또는 다음 개념으로 넘어간다.

### 4. 응답 신호와 질문 관계 알리기

사용자 답변 뒤, 다음 질문을 내기 전에 짧은 응답 신호를 먼저 출력한다. 사용자가 현재 답변의 상태와 다음 질문의 관계를 알 수 있어야 한다.

- 답변의 상태를 한 문장으로 알린다. 예: `핵심을 잘 짚었습니다.`, `방향은 맞지만 한 가지 구분을 더 확인하겠습니다.`, `이 부분은 아직 보완이 필요합니다.`
- 정답 전체나 최종 점수, 상세 첨삭은 밝히지 않는다. 상태 문장은 실제 답변 분석에 근거해야 하며, 빈 칭찬이나 정해진 의사구를 반복하지 않는다.
- 꼬리 질문이면 사용자의 실제 발언과 연결해 `방금 {답변 근거}라고 하신 부분을 이어서 보겠습니다. 이는 방금 답변에서 파생된 꼬리 질문입니다.`처럼 관계를 밝힌다.
- 다음 개념의 메인 질문이면 `여기까지가 {현재 개념}에 대한 질문이었습니다. 이제 다음 개념으로 넘어가겠습니다.`라고 전환을 알린다.
- `모르겠어요/패스` 뒤에는 `괜찮습니다. 이 쟁점을 좁혀서 다시 묻겠습니다.`라고 알린 뒤 힌트와 질문을 제시한다.

### 5. 꼬리 질문

`{question_phase}=detail`의 답변을 분석한 뒤 `{question_phase}=followup`으로 바꾼다.
키워드 분석에 근거해 꼬리 질문을 만든다 (개념당 최대 `{max_followups_per_concept}`개).
꼬리 질문은 미리 정해 둔 질문 순서가 아니다. 현재 답변의 검증되지 않은 주장부터 다뤄야
면접이 지원자의 사고를 따라간다.

다음 우선순위로 한 가지를 고른다.

1. **모호한 표현 확인**: 사용자가 쓴 단어의 의미나 주장 범위를 되묻는다.
   예: "'원자성을 지킨다'는 말이 임계 구역의 상호 배제를 뜻하나요, 원자적 연산을 뜻하나요?"
2. **오해 검증**: 답변 속 잘못된 인과나 일반화를 반례 또는 조건으로 검증한다.
3. **깊이 파기**: 답변이 맞게 짚은 핵심을 "왜/어떻게"로 더 들어간다.
4. **빈 곳 메우기**: 핵심인데 답에서 빠진 부분을 한 번 더 물어 끌어낸다.
5. **함정 찌르기**: 위키 `# 헷갈리는 점`의 함정은 사용자의 주장과 연결할 수 있거나,
   앞선 네 종류의 확인이 끝났을 때만 쓴다.

질문에는 고른 답변 근거를 드러낸다. 예: "여러 permit이면 Race Condition이 남는다고
하셨는데, permit이 1이면 이 판단은 어떻게 달라지나요?" 답변과 연결되지 않는 대표 질문으로
화제를 바꾸지 않는다.

꼬리 질문은 응답 신호 뒤에 아래 형식으로 표시한다.

> **[꼬리 질문 {번호}/{max_followups_per_concept}]**
> {질문}

질문은 하나씩이다. 꼬리 질문을 출력하면 **거기서 응답을 끝내고(턴 종료)** 사용자의 실제 답변을 기다린다.
답변이 도착한 뒤에만, 필요하면(그리고 한도 내에서) 다음 꼬리 질문으로 넘어간다.
여러 꼬리 질문을 한 응답에 몰아 쓰거나, 사용자 답변을 가정하고 이어가지 않는다.

면접 중 **위키에 없는 개념**이 답변에 등장하면 `{missing_concepts}`에 적어둔다 (지금 평가/정리하지 않음).
