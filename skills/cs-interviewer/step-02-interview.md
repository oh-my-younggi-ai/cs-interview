# Step 2: 면접 진행 - 대화의 출발점, 답변 분석, 연결 질문

면접의 핵심 루프. 첫 질문으로 이해의 출발점을 확인하고, 사용자가 실제로 한 말에서 다음 질문을
이어가며 깊이 파고든다. 위키 페이지의 순서가 아니라 면접 대화가 중심이다.

## RULES

- **한 번에 한 질문, 질문 직후 턴 종료.** 질문은 항상 한 개만 출력한다. 질문을 출력하면 그 응답을 거기서 끝내고
  사용자의 실제 답변을 기다린다. **HALT는 "응답을 멈추고 사용자 입력을 받는다"는 뜻이다.**
- **사용자 답변을 절대 대필/추측하지 않는다.** 한 응답 안에 사용자의 답변을 지어내 채우거나,
  답변이 온 것처럼 가정하고 평가, 다음 질문으로 넘어가서는 안 된다. 사용자 입력 메시지가
  실제로 도착했을 때만 다음 단계를 진행한다. (이걸 어기면 면접이 가짜가 된다.)
- 정답을 미리 다 알려주지 않는다. 면접관처럼 답변을 끌어내고 파고든다.
  (상세 평가, 모범답안은 세션 끝 step-03에서 정리한다.)
- 평가 기준은 해당 위키 개념 페이지다. 페이지의 `# 핵심 개념`, `# 헷갈리는 점`을 정답, 함정 기준으로 쓴다.
- `{wiki_root}`는 읽기만 한다. 면접 중 어떤 위키 파일도 수정하지 않는다.
- 면접관의 내부 처리 절차를 말하지 않는다. `힌트:`, `답변 근거:`, `파생된 꼬리 질문입니다` 같은
  표지는 출력하지 않는다.
- **EARLY EXIT** = 이 step을 즉시 중단하고 지정된 파일로 이동한다.


## PRECONDITION

`{current_index}`가 `{plan}` 길이 이상이면 모든 개념을 마친 것이다. 결과를 평가하고 기록해도 되는지
한 번 묻고 HALT한다. 사용자가 명시적으로 승인한 경우에만 **EARLY EXIT**로
`./step-03-evaluate-record.md`를 실행한다. 승인하지 않으면 기록 없이 종료한다.


## INSTRUCTIONS - 현재 개념 1개 처리

### 1. 개념 페이지 로드 (읽기 전용)

`{concept}` = `{plan}[{current_index}]`. 위키에서 해당 개념 페이지를 읽어 `# 한 줄 정의`,
`# 핵심 개념`, `# 면접 단골 질문`, `# 헷갈리는 점`을 파악한다. 대화를 이해하는 데 필요한 최소 용어를
`{core_terms}`로 정한다. 구현 세부사항이나 함정에만 등장하는 단어까지 확장하지 않는다.

현재 개념을 처음 시작할 때 `{question_phase}=opening`으로 설정한다. 앞선 대화에서 이미 의미가 드러난
용어와 주장은 다시 정의하게 하지 않는다.

### 2. 첫 질문

현재 주제의 핵심 의미를 사용자의 말로 드러낼 질문을 만든다. 독립 개념이라면 정의를 물을 수 있지만,
요청이 비교 주제이거나 가까운 개념이 함께 계획되어 있으면 차이, 선택 기준, 상황 설명으로 시작해도
된다. 질문 하나 안에서 여러 개의 독립 과제를 나열하지 않는다.

질문은 면접관이 실제로 말할 법한 문장으로 쓴다. 내부 체크리스트를 순서대로 읽듯이 질문하거나,
답변에 이미 나온 내용을 처음 듣는 것처럼 다시 묻지 않는다.

진행 번호, 단계명, 질문 유형은 사용자가 요청한 경우에만 표시한다. 평소에는 면접관의 말과 질문만
출력한다.

**여기서 응답을 끝낸다(턴 종료).** 사용자의 실제 답변이 도착할 때까지 아무것도 더 출력하지 않는다.
답변이 오기 전에는 step 3 이후로 진행하지 않는다.

### 3. 답변 분석

사용자 답변에서:
- **언급한 키워드/주장**을 뽑고, 각각을 `정확`, `모호`, `오해`, `누락`으로 분류한다.
- 위키 `# 핵심 개념` 대비 **빠뜨린 핵심**, `# 헷갈리는 점` 대비 **건드린 함정/오해**를 파악한다.
- 다음 질문의 출발점으로 삼을 `{conversation_anchor}`를 하나 고른다. 사용자가 실제로 말한 주장이나
  표현 중 모호하거나, 틀렸거나, 더 깊이 확인할 가치가 큰 것을 우선한다.
- **사용자 답변 원문**과 직전 질문 원문을 `{transcript}`의 현재 개념 항목에 그대로 보존하고,
  분석 메모(강점, 놓친 점, 첨삭거리, 후속 질문 거리, 대화 연결점)를 함께 누적한다. 원문은 요약하지 않는다.
  step-03 보고서가 대화를 원문 그대로 옮기고 틀린 답변 아래 첨삭을 단다.

답변이 불완전해도 후속 대화를 이어갈 주장이 있으면 같은 정의를 다시 요구하지 않는다. 그 주장의
의미, 근거, 동작 방식, 적용 조건을 물으며 정의의 빈 곳도 함께 확인한다.

후속 질문을 이해할 수 없게 만드는 선행 오해가 있으면 사용자가 한 말을 직접 받아 한 번만 확인한다.
한 번 확인한 뒤에도 틀리면 약점으로 남기고 같은 내용을 반복시키지 않는다. 다른 관점의 질문으로
넘어가거나 다음 개념과 연결한다.

사용자가 `모르겠어요`, `패스`라고 하거나 막혔을 때는 정답을 말하지 않는 짧은 단서 하나를 대화 속에
넣고 질문을 좁힌다. 단서를 별도 항목으로 선언하거나 `힌트:`라고 쓰지 않는다. 한 번의 단서 뒤에도
답하지 못하면 약점으로 기록하고 흐름을 진행한다.

### 4. 자연스러운 연결 문장

필요하면 질문 앞에 한 문장만 덧붙여 직전 답변을 받는다. 이 문장은 평가표를 읽는 용도가 아니라 다음
질문으로 자연스럽게 이어 주는 용도다.

- 사용자가 쓴 표현을 필요한 만큼만 받아서 묻는다. 매번 `방금 ...라고 하셨는데`를 반복하지 않는다.
- `정확합니다`, `방향은 맞습니다` 같은 정형화된 판정 문장을 습관적으로 붙이지 않는다.
- 질문이 왜 꼬리질문인지, 어떤 내부 우선순위로 골랐는지 설명하지 않는다.
- 가까운 개념으로 넘어갈 때는 공식적인 종료 선언 대신 앞선 답과 다음 개념을 잇는 질문을 사용한다.
- 실제로 주제가 크게 바뀔 때만 짧게 전환을 알린다.

### 5. 연결 질문

첫 답변을 분석한 뒤 `{question_phase}=followup`으로 바꾼다. 답변 분석에 근거해 연결 질문을 만든다.
질문 수는 개념당 최대 `{max_followups_per_concept}`개다. 연결 질문은 미리 정해 둔 질문 순서가 아니다.
현재 답변의 검증되지 않은 주장부터 다뤄야
면접이 지원자의 사고를 따라간다.

다음 기준으로 대화 가치가 가장 큰 한 가지를 고른다. 사용자가 원리나 인과를 설명했다면 표현을
교정하기보다 그 설명을 검증하거나 더 깊이 묻는 쪽을 우선한다. 용어의 모호함은 해석에 따라 답의
옳고 그름이 달라질 때만 먼저 확인한다.

1. **원리 파고들기**: 답변이 맞게 짚은 핵심을 `왜`, `어떻게`로 더 들어간다.
2. **인과와 경계 검증**: 답변 속 잘못된 인과나 일반화를 조건 또는 반례로 확인한다.
3. **의미 있는 모호함 확인**: 해석에 따라 판단이 달라지는 표현의 뜻이나 범위를 되묻는다.
4. **빈 곳 메우기**: 대화 흐름에 필요한 핵심인데 답에서 빠진 부분을 끌어낸다.
5. **함정 확인**: 위키 `# 헷갈리는 점`의 함정은 사용자의 주장과 직접 연결될 때만 쓴다.

질문 자체가 `{conversation_anchor}`와 의미상 이어져야 한다. 연결을 보여주기 위한 정형 문구를 덧붙이는
것으로 대신하지 않는다. 답변과 연결되지 않는 대표 질문으로 화제를 바꾸지 않는다.

질문은 하나씩이다. 연결 질문을 출력하면 **거기서 응답을 끝내고(턴 종료)** 사용자의 실제 답변을
기다린다. 답변이 도착한 뒤에만 필요하면 다음 연결 질문으로 넘어간다. 여러 질문을 한 응답에 몰아
쓰거나 사용자 답변을 가정하고 이어가지 않는다.

면접 중 **위키에 없는 개념**이 답변에 등장하면 `{missing_concepts}`에 적어둔다 (지금 평가/정리하지 않음).

### 6. 다음 개념으로

현재 개념의 메모를 `{transcript}`에 마무리한다 (강점 / 놓친 점 / 잠정 평가).
가까운 개념으로 넘어갈 때는 현재 답변과 다음 개념을 잇는 질문을 만든다. 상세 피드백은 끝에 남긴다.
주제가 크게 달라지는 경우에만 전환을 짧게 알린다.

`{current_index}` += 1.

`{current_index}`가 `{plan}` 길이 이상이면 평가와 기록 여부를 묻고 HALT한다. 명시적으로 승인받은
경우에만 **EARLY EXIT**로 `./step-03-evaluate-record.md`를 실행한다.
아니면 이 step의 INSTRUCTIONS를 다음 개념으로 반복한다.

사용자가 `넘어가자`, `패스`라고 하면 답변을 지어내거나 평가하지 않고 현재 질문을 건너뛴 뒤, 앞선
대화와 이어지는 다음 질문을 하나 한다.

사용자가 면접을 중단하거나 스킬 자체에 대한 대화로 전환하면 즉시 면접을 멈춘다. 이를 세션 완료로
간주해 평가하거나 기록하지 않는다. 사용자가 진행한 내용의 평가나 저장을 명시적으로 요청한 경우에만
`./step-03-evaluate-record.md`로 이동한다.
