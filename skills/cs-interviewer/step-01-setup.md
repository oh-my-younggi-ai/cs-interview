# Step 1: 셋업 - 위키 로드, 기록 부트스트랩, 출제 계획

## RULES

- `{wiki_root}`는 읽기만 한다.
- 인덱스 제목이나 미작성 교차링크를 출제 후보로 만들지 않는다.
- **EARLY EXIT**는 현재 step을 중단하고 지정된 파일로 이동한다.

## INSTRUCTIONS

### 1. 위키 로드

`{wiki_root}`와 루트 `index.md`가 존재하는지 확인한다.

- 없거나 루트 인덱스에 분야 링크가 없으면 승인된 로드맵이 없다고 알리고 HALT한다.
- 루트 인덱스에서 `/{category}/index.md` 형식의 분야 링크만 읽는다.
- 각 분야별 `index.md`에서 `##` 큰 토픽과 그 아래 목록 링크를 순서대로 읽어 `{wiki_topics}`를 구성한다.
- 실제로 존재하는 페이지를 가리키고 frontmatter가 `type: CS Concept`인 링크만 `{wiki_concepts}`에 넣는다.
- 각 후보에 concept ID, 분야, 큰 토픽, `frequency`, `difficulty`, `description`을 가능한 만큼 보관한다.

다음 항목은 `{wiki_concepts}`에 넣지 않는다.

- 루트 인덱스의 분야 링크
- `#` 분야 제목과 `##` 큰 토픽 제목
- 큰 토픽 밖에 놓인 링크
- `/.../index.md` 링크
- 존재하지 않는 페이지를 가리키는 링크
- 개념 페이지 본문의 미작성 지식 교차링크

큰 토픽이 있어도 출제 가능한 개념 링크가 없으면 작성된 개념 페이지가 없다고 알리고 HALT한다.

### 2. 기록 저장소 부트스트랩

`{records_root}`가 없으면 만들고 `{records_format}`에 따라 초기화한다.

- `log.md`: `# 면접 기록 로그` 헤딩
- `mastery.md`: `# 숙련도 (Mastery)`와 빈 표 헤더
- `sessions/` 디렉터리

`mastery.md`를 읽어 `{mastery}`를 로드한다. 처음이면 비어 있다.

### 3. 세션 범위와 길이 결정

요청에 단서가 없을 때만 주제 범위와 개념 수를 한 번에 짧게 묻는다.

- 분야 지정: 해당 분야의 모든 큰 토픽 아래 개념 링크
- 큰 토픽 지정: 해당 `##` 아래 개념 링크
- 정확한 개념 지정: 해당 개념 페이지 하나
- 범위 없음: 전체 `{wiki_concepts}`

같은 이름의 큰 토픽이 여러 분야에 있거나 요청이 여러 범위로 해석되면 한 번 확인하고 기다린다.
선택한 범위에 개념 링크가 없으면 빈 로드맵 영역임을 알리고 다른 범위를 고르거나 먼저 정리하도록
제안한 뒤 HALT한다. 길이를 지정하지 않으면 `default_session_size`를 사용한다.

### 4. 출제 계획

`{topic_scope}`에 맞는 실제 개념 링크로 후보 풀을 좁힌다. 후보는 중복 없이 구성한다.

- 약 60%는 `{mastery}`에서 약점 표시가 있거나 최근 평가가 보통 이하인 개념을 우선 선택한다.
- 약 40%는 나머지 후보에서 무작위로 뽑고 같은 조건이면 `frequency: high`를 조금 우대한다.
- `{mastery}`가 비어 있으면 전체를 무작위로 뽑되 `frequency: high`를 우대한다.
- 후보가 `{session_size}`보다 적으면 있는 만큼만 선택한다.

계획에는 각 개념의 `분야 > 큰 토픽 > concept ID`를 표시한다. 계획을 제시한 뒤 HALT하고 사용자
확인이나 조정 요청을 기다린다. 조정 요청이면 같은 후보 규칙 안에서 `{plan}`을 고쳐 다시 제시한다.

확인되면 `{current_index} = 0`으로 설정하고 **EARLY EXIT**로 `./step-02-interview.md`를 실행한다.
