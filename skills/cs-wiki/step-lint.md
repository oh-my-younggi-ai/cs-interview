# Step Lint: 위키 점검

위키의 지식 내용과 로드맵 구조를 점검한다. 문제를 먼저 보고하고 사용자 승인 후에만 수정한다.

## RULES

- 발견한 문제를 자동 수정하지 않는다.
- 점검 중에는 `{wiki_root}`를 읽기만 한다.
- 비어 있는 큰 토픽은 오류가 아니라 아직 채우지 않은 학습 영역이다.

## INSTRUCTIONS

### 1. 로드맵 구조 점검

- 루트 인덱스에는 존재하는 분야별 `index.md` 링크만 있는가.
- 모든 분야 디렉터리가 루트 인덱스에 정확히 한 번 연결되어 있는가.
- 분야별 인덱스가 `#` 분야 제목과 하나 이상의 `##` 큰 토픽을 가지는가.
- `##` 아래 목록 링크만 작성된 개념으로 사용되는가.
- `###` 이하의 분류나 큰 토픽별 하위 디렉터리가 생기지 않았는가.
- 모든 개념 페이지가 같은 분야의 큰 토픽 하나 아래에 정확히 한 번 등록되어 있는가.
- 인덱스의 개념 링크가 실제 `type: CS Concept` 페이지를 가리키는가.
- 개념 페이지가 루트 인덱스나 여러 큰 토픽에 중복 등록되지 않았는가.

### 2. 지식 내용 점검

- **모순**: 페이지 간 설명 충돌
- **낡은 서술**: 새 정보로 갱신할 내용
- **고아 페이지**: 인덱스 미등록 또는 인바운드 링크가 없는 페이지
- **누락 개념**: 본문에서 언급됐지만 자체 페이지가 없는 중요 개념
- **끊긴 구조**: 누락된 교차링크, 빈 핵심 섹션, 잘못된 경로
- **분류 문제**: 주 학습 맥락과 큰 토픽이 맞지 않거나 중복 등록된 상태

### 3. 보고

로드맵 구조, 분류 문제, 모순, 낡은 서술, 고아 페이지, 누락 개념, 끊긴 구조로 나눠 위치와
권장 조치를 보고한다. 빈 큰 토픽은 문제 목록에 넣지 않고 학습 현황을 요청받았을 때만 요약한다.

### 4. 수정

사용자가 승인하면 페이지 작업은 `./step-ingest.md`를 따르고 분야나 큰 토픽 변경은 승인된 범위만
반영한다. 처리한 내용은 `log.md`에 점검 기록으로 남긴다.

작업 완료 후 추가 요청이 있으면 `./step-01-route.md`로 다시 분류한다.
