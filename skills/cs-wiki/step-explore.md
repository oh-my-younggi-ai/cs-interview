# Step Explore: 대화 탐색과 추천 정리

루트와 분야별 인덱스에서 학습 범위를 찾고 대화로 개념을 탐색하거나 다음 학습 주제를 추천한다.
대화에서 나온 개념은 신규, 갱신, 변경 없음으로 나눈 뒤 승인된 변경만 `step-ingest`로 넘긴다.

## RULES

- 한 번에 한 질문이나 제안만 하고 사용자 답을 기다린다.
- 사용자 답변을 대신 만들거나 추측해 이어가지 않는다.
- `##` 큰 토픽은 학습 범위이며 작성된 개념이 아니다. 실제 개념 페이지 링크만 기존 지식으로 판정한다.
- 분야와 큰 토픽을 자동으로 추가하거나 바꾸지 않는다.
- 위키 파일은 사용자 승인 전까지 만들거나 고치지 않는다.
- `{explore_mode}`는 `discuss` 또는 `recommend`여야 한다.
- 학습 체크리스트는 대화 진행용 상태이며 위키의 고정 `##` 큰 토픽을 추가, 변경, 완료 처리하지 않는다.

## 공통: 학습 범위 찾기

1. 루트 `index.md`의 분야 링크를 읽는다.
2. 관련 분야별 `index.md`에서 고정된 `##` 큰 토픽과 그 아래 개념 링크를 파악한다.
3. 사용자가 분야나 큰 토픽을 지정했으면 실제 인덱스에 있는지 확인한다.
4. 대화 맥락으로 분야와 큰 토픽이 하나로 좁혀지면 자동으로 선택한다.
5. 여러 큰 토픽이 같은 정도로 가능하면 가장 중요한 구분 하나만 묻고 기다린다.
6. 맞는 큰 토픽이 없으면 가까운 위치와 로드맵 변경안을 제시하고 승인을 기다린다.

확정한 값을 `{target_category}`와 `{target_large_topic}`에 보관한다.

## A. recommend

### 1. 위키 현황 파악

사용자가 지정한 범위가 있으면 그 범위에서, 없으면 전체 분야에서 다음을 확인한다.

- 개념 링크가 없는 큰 토픽
- 연결된 개념 수가 적은 큰 토픽
- 이미 작성된 개념과 자주 함께 묻지만 아직 페이지가 없는 개념
- 면접 빈출도와 선수 지식 관계

개념 링크 수는 학습 현황의 신호로만 쓰고 완료 여부로 단정하지 않는다.

### 2. 갭 기반 추천

고정된 큰 토픽 안에서 아직 작성되지 않은 고빈출 개념을 2개에서 5개 고른다. 각 추천에
`분야 > 큰 토픽 > 개념`과 추천 이유를 붙인다. 이미 링크된 개념은 신규 추천에서 제외한다.

### 3. 선택 후 분기

- 사용자가 추천을 고르면 `{target_concept}`와 그 추천의 분야, 큰 토픽을 보관하고 `{explore_mode}=discuss`로 전환한 뒤 아래 B로 진행한다.
- 추천 선택이나 "이걸 정리해줘"라는 요청만으로 `step-ingest`로 이동하지 않는다. 먼저 해당 개념을 사용자와 학습하는 대화를 진행한다.
- 사용자가 학습 대화를 마치고 위키 정리를 명시적으로 승인했을 때만 B의 개념 추출부터 진행한다.

## B. discuss

### 1. 대화

확정한 분야와 큰 토픽을 학습 범위로 삼는다. 사용자가 주제를 고르면 그 개념을 이해하는 데 필요한
핵심 학습 항목 3개에서 7개를 `{learning_checklist}`로 만든다. 항목은 큰 개념 단위로 정하고,
`미시작`, `학습 중`, `완료` 상태를 가진다. 첫 응답에서는 체크리스트를 보인 뒤 첫 `학습 중` 항목에
대한 진단 질문 하나만 던지고 답변을 기다린다. 정의, 필요성, 예시와 다음 항목의 정답을 먼저
설명하지 않는다.

그 다음부터는 사용자의 답변에서 정확히 이해한 부분, 빠진 핵심 용어, 오해를 구분한다. 사용자가
질문하거나 보충 설명이 필요할 때에만 해당 항목의 정의, 필요성, 예시를 필요한 범위로 설명한다.
사용자가 해당 항목을 정확한 핵심 용어로 설명하거나 적용할 수 있으면 `완료`로 표시하고, 다음 미시작
항목 하나를 `학습 중`으로 바꾼 뒤 그 항목의 진단 질문 하나를 던진다. 체크리스트는 처음 만들 때와
상태가 바뀔 때 보여준다. 사용자의 이해를 확인하지 않은 항목을 설명만으로 `완료` 처리하지 않는다.
모든 항목이 완료되어도 위키 정리로 자동 이동하지 않고, 사용자가 학습 종료와 정리를 명시적으로
승인할 때까지 대화를 이어간다. 인덱스는 대화의 지도이며 질문 순서를 고정하는 대본이 아니다.

설명 전반에서 핵심 전문 용어와 키워드는 정확한 명칭으로 먼저 쓴 뒤 정의한다. 비유가 전문 용어를
대체하게 설명하지 않으며, 사용자가 요청할 때만 보조 설명으로 비유를 사용한다.

### 2. 개념 추출

사용자가 학습 대화를 마치고 정리를 승인하면, 대화에서 다룬 내용 중 저장할 가치가 있는 구체적인 CS 개념을 `{surfaced_concepts}`에 담는다.
큰 토픽 제목 자체는 개념 후보로 넣지 않는다.

### 3. 위키 대조

각 개념을 분야별 인덱스의 실제 개념 링크와 해당 페이지에 대조해 `{surfaced_changes}`로 분류한다.

- **신규**: 개념 페이지가 없고 인덱스에도 링크가 없다.
- **갱신**: 기존 페이지가 있지만 대화에서 정확한 새 설명, 예시, 함정, 질문, 연결이 나왔다.
- **변경 없음**: 대화 내용이 기존 페이지에 이미 충분히 반영되어 있다.
- **구조 문제**: 페이지와 인덱스 중 한쪽에만 존재한다. 중복 생성하지 않고 복구 후보로 둔다.

신규와 갱신 후보마다 주 분야와 큰 토픽을 하나 정한다. 여러 위치가 가능하고 맥락으로 결정할 수
없으면 사용자에게 한 번 묻는다.

### 4. 제안 후 승인

신규와 갱신 후보만 목록으로 제시하고 어떤 변경을 반영할지 승인받는다. 변경 없음과 구조 문제는
별도 상태로 짧게 알린다.

### 5. 정리

승인된 개념을 하나씩 `./step-ingest.md` 절차로 작성하거나 갱신한다.

작업 완료 후 추가 요청이 있으면 `./step-01-route.md`로 다시 분류한다.
