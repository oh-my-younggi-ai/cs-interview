# Step Ingest: 개념 정리

개념을 OKF 페이지로 작성하거나 갱신하고 교차링크, 분야별 인덱스, 로그를 유지한다.

## RULES

- AI 자체 지식을 기본 출처로 사용한다. 사용자가 자료나 링크를 주면 반영하고 `# Citations`에 남긴다.
- 페이지를 덮어쓰지 않고 기존 구조를 보존하며 병합한다.
- `{wiki_root}` 밖에는 쓰지 않는다.
- 면접 질문과 함정을 반드시 포함한다.
- 분야와 큰 토픽을 자동으로 추가, 삭제, 이름 변경, 재정렬하지 않는다.
- 개념 페이지를 큰 토픽별 하위 디렉터리에 넣지 않는다.

## INSTRUCTIONS

### 1. 분야와 큰 토픽 확정

1. 루트 `index.md`의 분야 링크를 읽는다.
2. `{target_concept}`과 요청 맥락에 맞는 분야별 `index.md`를 읽는다.
3. 기존 `##` 중 개념의 주 학습 맥락에 맞는 하나를 `{target_large_topic}`으로 정한다.
4. 선택한 분야를 `{target_category}`로 정한다.

사용자가 분야나 큰 토픽을 지정했어도 실제 인덱스에 존재하는지 확인한다. 개념이 여러 큰 토픽에
동등하게 걸치면 사용자에게 한 번 묻고 기다린다. 맞는 위치가 없으면 가까운 기존 위치와 로드맵
변경안을 제시하고 사용자 승인 전에는 분야 링크나 큰 토픽을 만들거나 바꾸지 않는다.

### 2. concept ID와 기존 페이지 확인

- 개념 페이지는 분야 디렉터리 바로 아래에 둔다.
- 파일명은 영문 `kebab-case`로 정한다.
- concept ID는 `{target_category}/{slug}` 형식으로 정한다.
- 같은 개념의 기존 페이지가 있으면 읽고 새 내용을 병합한다.
- 페이지와 인덱스 링크 중 한쪽만 존재하면 구조 문제로 보고하고 승인을 기다린다.
- 기존 개념이 다른 큰 토픽 아래에 있으면 자동으로 이동하지 않는다.

### 3. 내용 작성

`concept-template.md` 형식으로 작성한다.

- `# 한 줄 정의`, `# 핵심 개념`은 구조적 마크다운을 우선한다.
- `# 면접 단골 질문`에는 질문과 평가 포인트를 적는다.
- `# 헷갈리는 점 / 함정`에는 꼬리질문이 파고들 지점을 적는다.
- `difficulty`, `frequency`, `tags`, `description`, `timestamp`를 채운다.
- 사용자가 자료를 주면 `# Citations`에 남긴다.

### 4. 교차링크

- 본문에서 언급한 관련 개념을 bundle-relative 링크로 연결한다.
- 대상 페이지가 아직 없어도 본문 교차링크는 허용한다.
- 관련된 기존 페이지에 역링크를 추가한다.
- 여러 분야에 걸치는 개념은 복제하지 않고 주 위치 한 곳과 교차링크로 표현한다.

### 5. index 갱신

- 분야별 `index.md`의 `{target_large_topic}` 바로 아래에 개념 링크를 추가하거나 갱신한다.
- 분야별 인덱스 전체에서 같은 개념 링크가 정확히 한 번만 존재하게 한다.
- 설명은 페이지의 `description`을 가져오고 빈출도가 있으면 `(freq: ...)`를 덧붙인다.
- 기존 페이지를 갱신하면 링크 위치를 유지하고 설명과 빈출도만 동기화한다.
- 루트 `index.md`에는 분야별 `index.md` 링크만 유지하고 개념 페이지 링크를 추가하지 않는다.
- 해당 분야 링크가 루트에 없으면 로드맵 변경으로 취급하고 사용자 승인을 기다린다.

### 6. log 기록

오늘 날짜 섹션 아래에 다음 형식으로 기록한다.

```text
* **정리**: [{title}](/{concept-id}.md) {신규 작성 | 갱신}. 큰 토픽: {target_large_topic}. {변경 요약}
```

### 7. 자체 점검

- 본문 교차링크와 필요한 역링크를 확인한다.
- 개념 페이지가 올바른 `##` 아래에 정확히 한 번 등록됐는지 확인한다.
- 루트 인덱스에 개념 링크가 없고 분야 링크가 유지되는지 확인한다.
- 개념 페이지가 분야 디렉터리 바로 아래에 있는지 확인한다.
- `log.md` 기록과 필수 본문 섹션을 확인한다.
- 경로 실수로 깨진 링크가 없는지 확인한다.

문제를 발견하면 자동 수정하지 않고 보고한 뒤 사용자 승인을 기다린다. 문제가 없으면 점검 통과로 보고한다.

### 8. 요약 보고와 다음 토픽 추천

변경한 개념, 분야, 큰 토픽, 파일, 점검 결과를 짧게 보고한다. 같은 큰 토픽이나 직접 연결된 다른
큰 토픽에서 이어가기 좋은 미작성 개념을 2개에서 3개 제안한다.

작업 완료 후 추가 요청이 있으면 `./step-01-route.md`로 다시 분류한다.
