# 한 줄 정의

**UDP(User Datagram Protocol)**는 연결 설정과 연결 상태 유지 없이 독립된 데이터그램을 전송하는 전송 계층 프로토콜이다.

# 핵심 개념

## 비연결형 데이터그램

- 연결을 설정하는 handshake 없이 데이터그램을 바로 보낸다.
- 각 데이터그램은 독립적으로 처리되며, 서버가 응답 데이터그램을 보내더라도 UDP 연결 상태가 생기는 것은 아니다.
- 비연결형은 비동기와 다른 개념이다. 비동기는 호출자가 결과를 기다리지 않고 다른 작업을 계속하는 실행 방식이다.

## 제공하지 않는 신뢰성 기능

- UDP 자체는 데이터그램의 전달, 순서, 중복 제거를 보장하지 않는다.
- TCP와 달리 Sequence Number, ACK, 재전송을 통한 복구를 기본 제공하지 않는다.
- 애플리케이션이 신뢰성이나 순서 보장이 필요하면 필요한 범위에서 직접 구현해야 한다.

## 사용 조건

- 최신 데이터의 가치가 이전 데이터보다 크고 일부 유실을 허용할 수 있는 실시간 위치 갱신, 음성, 게임 상태 전송에 적합하다.
- [TCP](/network/tcp.md)보다 무조건 빠른 프로토콜이 아니라, 필요한 보장과 복구 비용이 다른 프로토콜이다.

# 면접 단골 질문

- Q: UDP가 비연결형이라는 것은 무엇을 뜻하나요?
  - 포인트: handshake와 연결별 상태가 없고, 각 데이터그램을 독립적으로 처리함. 요청과 응답의 부재를 뜻하지 않음.
- Q: UDP는 유실된 데이터그램을 어떻게 처리하나요?
  - 포인트: UDP 자체는 복구하지 않으며 필요하면 애플리케이션이 처리.
- Q: UDP와 비동기의 관계를 설명해보세요.
  - 포인트: 비동기는 실행 방식, UDP 비연결형은 프로토콜의 연결 설정과 상태 관리 특성.

# 헷갈리는 점 / 함정

- **"UDP는 응답을 받을 수 없다"** - UDP 애플리케이션도 요청과 응답을 주고받을 수 있다.
- **"비연결형이므로 송신자는 기다릴 수 없다"** - 대기 여부는 애플리케이션의 동기 또는 비동기 설계 문제다.
- **"UDP는 유실이 생기지 않는다"** - UDP는 유실을 복구하거나 순서를 보장하지 않는다.
